# Lean proofs

Lean 4 proofs of every statement the 2024 thesis makes on its own authority, of the
corrections made in the revised edition, and of the bridges to `openai/math`. The status of each
thesis statement and the name of its proof are in [`../thesis/CLAIMS.md`](../thesis/CLAIMS.md).

Toolchain `leanprover/lean4:v4.35.0`, Mathlib `v4.35.0`.

## Build

```text
cd lean
lake exe cache get
lake build
```

`lake build` checks every proof; it takes about two minutes once the Mathlib cache is in place.
`lake build HypergraphDualization.Connections` (or any other module) checks one module and its
imports.

On Windows with long paths disabled, the Mathlib cache does not unpack under a deep directory.
Map a drive letter to the repository first (`subst H: <repository path>`) and run `lake` from
`H:\lean`. Where `cache.mathlib.org` is unreachable, `MATHLIB_CACHE_DEBUG_USE_LEGACY=1` reads the
same cache from Mathlib's Azure storage account.

## Trust base

General theorems depend only on the axioms `propext`, `Classical.choice` and `Quot.sound`
(`#print axioms`). Facts about named finite instances are proved by evaluation with
`native_decide`, which also trusts the Lean compiler; their docstrings and module headers say
so. A kernel-only check (`decide +kernel`) succeeds on the smallest instances but did not finish
on the larger ones within 40 minutes.

## Regenerating the generated modules

From the repository root, with the Python package importable:

```text
python lean/tools/gen_instances.py     # Data.lean from data/instances
python lean/tools/gen_trees.py         # TreeFacts.lean from results/*.fk-a.modified.json
```
